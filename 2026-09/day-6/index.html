  • Keep two backlogs: one for the work itself, one for improving the factory. They are orthogonal.
  • More and more of your work is now on the second one. When a run goes wrong, fixing its output by hand fixes one run; fixing the machine fixes every run after it.
  • Tie it to Tuesday's toast (“You burn, I'll scrape”): build quality in by changing the machine that made the mistake.
  • Kief Morris calls this working on the loop (Humans and Agents in Software Engineering Loops): humans run the why loop, deciding what the software should do; agents run the how loop that builds it. When the output is wrong, change the harness, not the artefact. Reviewing every line is being in the loop, and it becomes the bottleneck.
  • “Here's a way to structure that second backlog.”

The Improvement Kata

⏱ 09:57–10:00 · 3 min
🎤 Jeremy
  • North Star: where you're heading, which you may never reach. E.g. a dark factory: concept to cash, no bugs, no human intervention.
  • Current condition: where your factory is today. E.g. given a story, it produces code.
  • Target condition: the next place you want to be, close enough to reach soon. E.g. given fleshed-out stories, it produces deploy-ready code with no intervention.
  • Obstacles: you can't see the way through yet. Take them one at a time, each a small Plan-Do-Check-Act loop.
  • Who does what: you set the North Star and agree the target condition. The robot is good at the numbers that describe the current condition, which are tedious to gather by hand.
  • Keep it under five minutes; they learn it by doing it next.

  • A fix, added to the tutorial this week (tutorial PR #8). Since iteration 004 every machine has had a folder, .assembly-lines/.machines/<name>/, “holding its configuration”, but no iteration said what goes in it. Most factories still keep machines' prompts in code, and the harness reads the student's own AGENTS.md or CLAUDE.md above the target.
  • Iteration 005a makes the folder the configuration directory of the harness that runs the machine: its AGENTS.md (instructions, lens included), its harness and model, and its own copy of the login, kept out of Git.
  • Two rules: a machine runs on its own configuration and no other (not yours, not another machine's, not files in or above the target); a machine signs in with its own login, or its provider's API key, or the factory says it can't before running anything.
