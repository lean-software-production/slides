  • Iteration 006, watching: start a run and get the terminal back, attach later from another command, see each machine's output live and the tokens it spends, keep a record you can read tomorrow. One run at a time. Each machine now runs as an ACP agent.
  • Iteration 007, steering: send a message to a named machine while it runs; it arrives at its next step. Messages to a machine that isn't running are refused, and a message lasts only for that run.

Framing: audience, outcomes, concepts, logistics

Learning outcomes

  • Describe how their homework went, and say when looking at the same work through several models or lenses is worth its cost.
  • Use the Improvement Kata on their own factory: choose a North Star, describe the current condition, set a target condition for the end of next week, and name the next step.
  • Say when to watch a run, when to steer it, and when to change the seed, plan or prompt instead, and know the weekend homework.
  • Say what they still want to figure out for the course to be a valuable use of their time.

Key concepts

  • Fix the machine, not the code: when a run goes wrong, the job is to change the factory so the next run goes right, not to repair this run's output by hand.
  • Kaizen: small, continuous improvements. Keep two backlogs, one for the work and one for improving the factory; more and more of your work is the second.
  • On the loop: Kief Morris's framing in Humans and Agents in Software Engineering Loops. Humans run the why loop (what the software should do); agents run the how loop (building it). Working on the loop means changing the harness rather than the artefact; being in the loop, reviewing every line, becomes the bottleneck.
  • The Improvement Kata: a way to structure kaizen. Pick a North Star, describe the current condition, set a target condition, then work through the obstacles one PDCA step at a time.
  • Watch, steer, change: watch to understand a run; steer to correct this run; change the seed, plan or prompt when the lesson should last.
